# splify2

Управление и интерфейс поверх движка [steer](https://github.com/xyzmean/steer).

Разделение простое: steer решает, куда идёт трафик, и больше ничего. splify2 решает
всё остальное — какие списки включены, какой туннель считается основным, что показать
человеку. Движок без мнения, мнение здесь.

## Почему интерфейс написан заново

splify 1 умел один туннель и три жёстко заданных списка, и это было зашито в форму
настроек: галочка «ipsum», галочка «ru», галочка «geoblock». Модель движка другая —
**упорядоченные каналы** `(кто, что) → выход`, и выходов может быть сколько угодно.
Переклеить старую форму под это не получалось: пришлось бы прятать главное, что
пользователь обязан понимать — что каналы проверяются сверху вниз и побеждает первый.

## Два входа: мастер и редактор

Интерфейс открывается в одном из двух видов, и решает это КОНФИГУРАЦИЯ, а не переключатель
в настройках.

**Мастер** — пока каналов нет. Один экран: вставить ссылку подписки, отметить сервисы,
нажать «Применить». Слов «канал» и «выход» на нём нет вовсе — их составляет код. Это не
упрощённая версия редактора, а другой вопрос: чтобы получить работающий VPN через редактор,
надо выучить четыре понятия, пройти три вкладки в верном порядке и знать, что каналы
проверяются сверху вниз. Для «хочу ютуб через VPN» это непроходимо.

Мастер трогает РОВНО свои две записи — выход `vpn` и канал `сервисы`. Настроенное руками он
переносит как есть и говорит об этом строкой на экране: иначе «простой режим» стал бы
способом молча снести чужую работу.

Адресные списки мастер не предлагает сознательно. Домены точнее — «пустить ютуб» работает
независимо от того, какой из десятков его адресов выдал DNS в эту минуту, — и это снимает
целый класс ошибок: включить одно и то же в двух формах стоит двойной памяти и двух каналов,
спорящих за одну цель. Хостинги и CDN (Cloudflare, Hetzner, `hodca` на 250 доменов) в мастере
тоже не показываются: они уводят в туннель куда больше, чем человек имел в виду.

**Редактор** — как только настройка появилась. Четыре вкладки ниже, и дорога обратно к
мастеру остаётся в углу: подписку меняют чаще всего остального, а в мастере это одно поле
вместо трёх экранов.

Почему не «всегда мастер по умолчанию»: он выражает не всякую настройку — несколько выходов,
свои подсети, failover, — и открывать его тому, у кого настроено больше, значит каждый раз
показывать неполную картину и заставлять из неё уходить.

## Редактор строится вокруг четырёх вещей:

- **Каналы** — ранжированный список. Порядок виден и меняется стрелками, потому что
  порядок *и есть* приоритет.
- **Выходы** — именованные. Канал указывает на имя, а не на устройство: failover
  переставляет устройство, не трогая ни один канал, и два канала могут вести в два
  разных туннеля одновременно.
- **Списки** — адресные и **доменные**, в одном месте. Доменный список — это то, что
  заставляет «пустить youtube» работать независимо от того, какой из десятков его
  адресов выдал DNS в эту минуту.
- **Состояние** — дословно от движка, включая «куда пойдёт этот адрес» и предупреждения
  вроде «у туннеля нет NAT»: без него маршрут применяется, счётчик растёт, а сайты
  молчат.

Стилистика Argon сохранена: палитра читает собственные CSS-переменные темы с
хекс-фолбэками, поэтому выбранный пользователем акцентный цвет подхватывается сам, а
тёмная тема определяется по фактическому фону страницы.

## Что откуда берётся

| | откуда |
|---|---|
| адресные списки по категориям | [xyzmean/ru-bypass-ipsets](https://github.com/xyzmean/ru-bypass-ipsets) |
| доменные списки | [itdoginfo/allow-domains](https://github.com/itdoginfo/allow-domains) (`Categories`, `Services`), зеркалируются там же |
| маршрутизация, fake-IP, наборы | [xyzmean/steer](https://github.com/xyzmean/steer) |

## Состояние

Работает на роутере: модель, мастер, страницы каналов, выходов, списков и состояния, бэкенд
rpcd, упаковка в `luci-app-splify2`.

```sh
cd ui && npm install && npm run build
```

Сборка проверяет себя сама: `scripts/check-dist.mjs` роняет её, если один чанк
оказывается доступен по двум URL — в splify 1 это стоило намертво сломанной вкладки,
потому что браузер загружал preact дважды.
